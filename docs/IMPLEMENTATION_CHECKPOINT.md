## Phone translation on my PC (2026-10-11, branch work, not merged or deployed)

- New reader translation engine **My PC (Koharu)** (`pc-koharu`): the phone sends the whole original page to the Mihon Together Translator's phone port (`:47824`, "Phone uses the PC translator" in `docs/KOHARU_TRANSLATION_PLAN.md`) and shows the PNG it returns. Code in `mihon.feature.translate`: `PcTranslator.kt` (client: health, pair, translate, unpair; connect 3 s, read 90 s; no proxy, system DNS, no HTTP cache; `PcAddress` parser; `PcTranslationEngine`, which re-finds a moved PC by name and re-encodes AVIF as PNG), `PcDiscovery.kt` (NsdManager, `_mihontogether._tcp`, TXT `name`), `PcPairing.kt` (controller plus the settings section and pairing dialog).
- Reader: `PageRenderingEngine` pages skip slicing; the PNG is cached as `<sha256(image|pc-koharu|target|)>-page.png` in the translation cache, so prefetch (current + 2), the Original toggle and cache reuse work as before. Unreachable or loading PCs (`PC_UNREACHABLE`, `PC_LOADING`) show the problem with Retry and are asked again on the next page turn; 401 (`PC_UNPAIRED`) stops the queue until paired again. Editing is unavailable for this engine (toast). Incognito treats it as local, like on-device.
- Pairing stores address, PC name and token (token as a private preference, like the Gemini key; not in backups). No manifest or network security change: the base config already permits cleartext (sources need it); NSD needs no permission on target SDK 36.
- Verified: `spotlessCheck testDebugUnitTest` and `assembleDebug`; 15 new client tests (fake interceptor, MockWebServer isn't in the project) and 5 new reader tests; the opt-in live test (`PC_TRANSLATOR_LIVE=1`, plus `PC_TRANSLATOR_CODE`/`PC_TRANSLATOR_PAGE`) against translator 0.2.0: health, 401 for an unknown token, pair, translate a Korean page (2.6 s), unpair. - **Text colors (2026-10-14, `fix/pc-translate-text-color`):** Berti's test showed red lettering in a black bubble translated into black text, invisible. Cause: Koharu's `normalize_text_color` (pinned commit) snaps colors with luminance ≤ 64 to black, and its luminance weights green heavily, so saturated red/blue/purple snap to black. The translator now measures each text region on the original page before rendering (`text_color.rs`; layer → `Presents` → content → `RecognizedFrom` → region `Geometry`) and puts a saturated color back when Koharu snapped it to black or white, using the most colorful half of the ink so glyph edges don't darken it; text whose color would melt into its background gets the measured ink or black/white. Best effort: a failure keeps Koharu's colors. Verified: `cargo test` (55, 9 new), `cargo build --release`, Berti's red bubble now renders "OF COURSE." in red, and the Japanese test page is unchanged (black text, blue title). Koharu's inpainting still leaves a faint trace of the original glyphs in that black bubble (upstream).
